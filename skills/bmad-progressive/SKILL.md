# BMAD Progressive Context

This is an interoperable workflow inspired by BMAD patterns, not a bundled copy of BMAD. Read
`references/stage-contracts.md` and preserve human-provided artifacts as authority.

## Choose the entry

- `idea`: intake -> product -> solution -> readiness -> build -> verify -> release -> learn.
- `plan-given`: validate the plan's executable gaps, then readiness or build.
- `execute-only`: convert the supplied authority into task packets; do not create a competing PRD.

## At each stage

1. Load the short router and active `CONTEXT.md` only.
2. Resolve its named working inputs and stable references.
3. Produce only its declared outputs; link to authoritative facts instead of duplicating them.
4. Run exit criteria and the cold walk test.
5. Record the checkpoint required by the selected autonomy policy.
6. Generate the next stage contract with freshness/provenance, then shed obsolete context.

Target 2,000–8,000 tokens per task context. When a source is too large, the context engineer
creates a narrow, attributable summary and records omitted areas. Never compress away a safety,
data, contract, or unresolved decision dependency.
