# Verification matrix

Use one row per requirement or material risk:

| Requirement/risk | Source | Implementation | Test/evidence | Result | Owner | Residual risk |
|---|---|---|---|---|---|---|

Minimum dimensions when applicable: functional journeys, data integrity, authentication and
authorization, abuse/security boundaries, privacy lifecycle, accessibility, performance,
compatibility, migrations, observability, backup/restore, deployment, rollback, and support/admin
operations. “File exists” and “builder says complete” are not verification evidence.
